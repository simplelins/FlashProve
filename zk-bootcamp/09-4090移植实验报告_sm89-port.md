## 若批准移植的精确改动（均在实验副本上做，不进仓库）

1. `k_ws<4,32>`：静态 `sh[NS][LANES][33]` → `extern __shared__`，launch 传 `NS*LANES*33*8` 字节，首次调用前 `cudaFuncSetAttribute(..., MaxDynamicSharedMemorySize, 59136)`（≤99KB ✓）。同模板 <5,16> 用量 38KB < 48KB 无需改。
2. `k_count` 家族：`COUNT_BITS 15→13`（4<<13=32KB ✓）。语义影响：bins 减少 ⇒ 计数分批多走（`iota ≤ COUNT_BITS`），正确性由既有 GPU-vs-CPU 对拍兜底；性能下降但小模型可接受。**需确认 small kit 的 table 行数 2^b ≤ 2^13**（line 558 有 guard 会明确报错）。
3. 重建后可能暴露下一个超限内核——迭代直到干净（未知数量，估计 0–5 个）。
4. 全程验证：`run_target_example.sh target_small_f2_roomy` 期望末行 YES。

# 附 2：cuBLAS int8 约束破案 + 终修（2026-11-06）

## 决定性实验（探针 /tmp/mscan10-11.cu，sm_89 + cuBLAS 13.2.2.2）
| 形状 | 结果 |
|---|---|
| m400 n2048 k16 ldc408 (%16=8) | **15** |
| m408 n2048 k16 ldc416 (%16=0) | **15** |
| m400 n2048 k16 ldc400 (=m, %16=0) | **0** |
| m408 n2048 k16 ldc408 (=m, %16=8) | **15** |
| m8/16/400/416, n32, k16, ldc=m | **全 0** |

**约束：int8 IMMA 接受 ⟺ ldc == m 且 m % 16 == 0**（C 无 padding 且行距 16 对齐）。
cp_commit 小 kit 的 sums 布局 ldc=m=408（%16=8）永远被拒 → 无法用参数重排修复。

## 终修（已在分支，commit 待构建验证）
gemm_tn 的 fallback 改为**对齐暂存区中转**：mp = m 上取整到 16；A 补零行拷入
scratch（mp×k）；单次 GemmEx 写 scratch（ldc=mp ✓ 约束满足，beta 语义由该次调用
保持）；cudaMemcpy2D 逐行拷回调用方的 C（真实布局 ldc=m）。数值与调用语义等价。

# 附 5：cublasLt 已排除，问题收窄到森林求和链内核（2026-11-07）

## 关键实验
1. **探针矩阵（/tmp/gprobe2.cu）**：对失败形状 (m192 n128 k512 batch4)，

# ✅ 附 8：全链路 YES —— RTX 4090 D 移植完成（2026-11-07）

## 根因（最终）
PackedSrc 的全局读补丁删除了 stage()，而 stage() 内置的 __syncthreads()
正是 set_powers()（thread 0 写 alpha 幂）对所有线程可见所需的屏障。
k_digits_poly 的 BYTE_FORM 路径在 init 后无自身屏障 → powers 读-写竞争 →
quad/数字位错 → lookup_tie 代数自检失败 → OWN_TEST → example.failed。
修复：init_values 尾部显式补回 __syncthreads()（commit 00dbfc62）。

## 完整成功记录（AGENTS 纪律格式）
```
# 构建：FP_ARCH=sm_89 OUT=$HOME/flashprove-exp/out23 bash prover/build.sh tests  → exit 0
# 示例：BUILD=out23/hc prover/examples/run_target_example.sh target_small_f2_roomy $WORK
#   → status 0
```
