## 5. L2-alt 的四堵墙（48GB 卡的完整教训，纲领 §7）

1. **status 7**（scales 过紧）→ worst_case.py 加粗 + e_res 降位 + wsums 重做；emb_bits 以实测修正；
2. **key-file 墙**：引擎房 24GiB（H100 常数）+2GiB 预留卡死 slab → 23GiB+1GiB（编译期适配）；
3. **entry 墙（死墙）**：折叠行 = 54×ell（2×27×ell），与模型大小无关 → 模型减半 + table 2^27；
4. **形状下限**：H×dh=d（shape-heads）、f=2·fe（MoE）、L/V 不可缩（调用形状下限）。

**缩放定律**：table 2^27 下 48GB 卡承载 ≈30G 参数；50G+ 需 64GB+；全尺寸 Maverick（464G）
需 80GB H100（L3/L4 的 GPU 步骤搁置于此——scales 管线的 CPU 步骤已全部验证可用）。

## 6. vLLM 服务（⑥）的坑位清单

- flashinfer JIT 需要 **curand.h**（pip CUDA 缺）→ 从系统 cuda-13.3 拷 curand*.h 进 pip 工具链 include；
- ninja 硬编码 `-L lib64`（pip 工具链只有 lib/）→ `ln -s lib lib64`；
- vLLM 引擎启动需 **ninja**（venv pip 装）+ VLLM_API_KEY + 五件套 reference 目录；
- serve.sh 自带的 make_model 参数（H=2）与硬编码 D=5120 矛盾——自备自洽形状的 reference；
- pytest 980 通过（服务类测试需上述修复）。
