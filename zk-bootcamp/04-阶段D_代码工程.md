## D1 · blocks/：共享证明库地图（1 课）

### 目标
建立"协议块 ↔ 头文件 ↔ 规则"的三向映射。这是读懂 prover/verifier 的地基。

### 讲义
**定位**（blocks/README）：纯 C++17 头文件（除 3 个 .cuh），无 CUDA 也能构建；含基础件
（field/hash/chain/code/tree/numbers）与**每个协议块的 plan_x / x_prove / x_verify 三件套**。
CPU 引擎下这些例程构成**参考证明器**（注意：仓库没有"在 CPU 上证明模型回复"的程序——
参考证明器只有例程级测试）。

**目录布局**（README 表，逐行记）：

| 目录 | 内容 |
|---|---|
| `base.h` | 整数别名、BLK_HD/BLK_REQUIRE、编译期设置 |
| `field/` | F、E=F[X]/(X³−c)、规范解析、等值向量、小多项式 |
| `code/` | 码=(length, message length, random tail)、编码、生成行乘积形 |
| `hash/` | BLAKE2b 规格（叶/顶点/轮次/参数摘要；起始值=盐+个性化） |
| `chain/` | FS 链+PoW（chain.h）、公开输入（public.h/Binder）、类型化轮次（rounds.h） |
| `tree/` | 完美二叉 Merkle、列+盐叶、批量开列 |
| `numbers/` | 参数、轮次误差、尺寸；Plan 与 plan_<block> |
| `iop/` | message/tensor/relation/context + 18 个协议块头文件 |
| `engine/` | 证明器重步骤统一接口（CPU 版 engine_cpu.h；GPU 接口同形） |
| `coins/` | 从 seed 按流派生私有随机数 |
| `frame/` | 文件周边：格式版本、参数文件、派生物 |
| `toy/` | toy 尺寸全流程（product.h 单次乘积、segments.h 链） |

**iop/ 的 18 块**（`send.h bat.h split.h hp.h psc.h line.h fold.h cs.h base_case.h iopp.h req.h
lkp.h rng.h batt.h foldeq.h lin.h link.h member.h`）——B4 的映射作业在此收尾。

**必须内化的十条规则**（blocks/README "Rules of the folder"，课堂逐条过）：
1. 单一命名空间 `blk`，include 一律 `-I blocks` 形式；
2. 域/哈希由编译开关选定（`-DBLK_FIELD=2`、`-DBLK_HASH=1`），宽度禁硬编码；
3. 索引与 fold 约定（A2 已学）；
4. 每块三件套；channel 校验轮次顺序与消息尺寸（错序/错尺寸=终止进程）；
5. 抽挑战前的一切都经"写入+吸收"单调用；只有对查询的回答（列/盐/兄弟）不吸收；
6. 顺序约束用类型系统实现（验证者消息按种类分组；seed 与其回答之间不许插别的挑战……）；
7. 两种失败：`BLK_REQUIRE`（程序 bug，进程终止）vs 返回 false（依赖证明字节，验证例程
   只能拒绝；一次读失败之后所有读都失败）；
8. 哪些 oracle 消息共树是 `iop/context.h` 的规则，共树必共开；
9. 私有随机性经 `Coins`；
10. `Binder` 把参数与陈述写进首查询；`Public<T>` 无 getter（A4 已学）。

**一条安全注记**（GAPS "What it does not say" #9）：直接调用 blocks/ 库的程序（绕过
`chain/closed.h` 合约）**可以被造出接受假声称**——至少一种方式在 toy 尺寸有效。cp_verify
未暴露这一点只是"读码结论"，不是测试结论。⇒ **永远用 cp_verify 验证**，不要自己拼库调用。

### 作业
1. `cd blocks && make`（或按 Makefile 构建 tests），跑测试，记录输出。
2. 读 `field/field.h` 头 100 行，确认 A1 的两条恒等式在代码/注释里的位置。
3. 完成 B4 的 iop 块映射表最终版（18 块全覆盖）。
4. 写 300 字：规则 7 的两失败模式为什么这样设计？（提示：验证器不能 crash on 恶意输入；
   程序 bug 应 fail-fast。）

## D3 · prover/ 架构与 CUDA（1 课 + 可选 GPU 实验）

### 目标
理解两个 GPU 程序的模块划分与数据流；知道哪些名字会误导；明确本机的实验边界。

### 讲义
**入口与命名陷阱**（prover/README，原文级要点）：
- `cp_commit`：main 在 `hash_commitment/hf_commit.cu`；**命令行与模型文件读取器在
  `weights_commitment/`**；
- `cp_prove`：main 在 `prover/cp_prove.cu`；`hash_commitment/hf_keeper.cu` 单独编译后链接；
  注意外层 `prover/` 目录=两个 GPU 程序，内层 `prover/` 子目录=cp_prove 本体；
- `head/stack.cuh` 是**层内子证明**的步骤，不是输出头的——第三个陷阱；
- `cp_commit` **内嵌验证器**：运行时以子进程跑 cp_verify 检查自己的产物；`build.sh` 把
  verifier 源码编译进去以拒绝坏配置。**cp_prove 两者都没有**——它不验自己（这就是"前端
  先验"义务存在的原因，C3/C5 已讲）。

**目录与证明顺序**（README 表的前七行按证明制作顺序排列）：
`attn`（注意力的模型算术+子证明）、`head`（输出头）、`engine`（GPU 模型引擎）、
`field`、`hash_commitment`（承诺主程序+keeper）、`hiding`（掩码相关）、`longrow`、
`prover`（cp_prove 本体）、`second_writing`、`weights_blocks`、`weights_commitment`
（cp_commit 的命令行/权重读取）、`common`、`tools`。子证明的轮次清单在
`prover/plan_rounds.h`、`head/plan_rounds.h`、`attn/plan_rounds.h`（blocks README 提到的
"lists of the sub-proofs' own rounds stand outside it"）。

**权重不落盘**：表本体不存，每批从模型权重文件重算所需部分，与存储的**一层哈希树**比对
（协议 §4）——省磁盘、防篡改靠树层级。

**构建与环境**：H100 80GB + CUDA 13.2 Update 2（nvcc 13.2.86；更新版 nvcc 不拦截构建但
不受支持）+ g++13 在 PATH 前 + SHA 扩展 CPU。production build = `prover/build.sh` 无参或
`serving` 开头；test build 接受测试选项、拒绝真模型文件。

**GPU 实验（可选）**：`examples/quickstart-gpu.sh`（build ~29 min 起、可静默 >15 分钟、
成功判据 = exit 0 + `quickstart-gpu: all steps ended as expected` + 每行 `Compiled by` 以
`release 13.2, V13.2.86` 结尾）。非 H100 硬件上这是**研究性实验**：失败不进课程成绩，
但日志（quickstart-gpu.log）是绝佳读码材料。全尺寸合成目标（280GB RAM，~42 min）见
`prover/examples/run_target_example.sh target_full_f2`。

1. 精读 `prover/README.md` 全文（含"directories"表），做一份"目录→证明阶段"映射图。
2. 读 `prover/docs/build.md` 的"Install the compiler"节，列出你机器缺什么（只列清单不安装）。

4. 读 `prover/docs/ends-in-short.md`，总结三种退出状态与"release 窗口"。

### 资料

five-values 校验）、`guide/performance.md`。

## D4 · 量化与 scales/（1 课）

### 目标
打通"浮点模型 → 整数模型 → 证明"的数据链路；理解 scales 公开/权重隐藏的边界与最坏情况界。

### 讲义
**链路**：GGUF/训练权重 → `scales/gguf_weights.py` 读入 → 校准集（`make_calibration_set.py`）
→ 每层右移/指数拟合（`fit_scales.py`、`calibrate.py`）→ 写出 `KL.bin` + 参数行 → 整数模型
（`model.py`）逐值对照浮点前向（`float_forward.py`）→ 策略表（`policy_tables.py`、
`words_to_policy.py`）。

**scales 的语义**（model.md §3）：每层 7 个右移（q/k/v/o/gate/up/down）+ 2 个 norm 的指数对
（M1/K1、M2/K2）+ softmax 移位 sh + rotary 开关 rp；MoE 层加 kr/kgR/kuR；最终 norm 的
MF/KF 与三个正则 eps。norm 用 isqrt 的整数 RMS（model.md §5：sigma = isqrt(Vx+eps)，Vx 可
超 64 位——扩域算术的用武之地之一）。

**最坏情况界**（`scales/worst-case-bounds.md`）：cp_commit 在承诺前仅凭权重+scales 推出
"任何 prompt 能把范围条件 1–8 的值推到多大"；文档自述**论证而非证明**（model.md §9 末）。
prover 的接受区间比 Model 定义域窄（limb 表示所致：32639/547599908735 两个截断，model.md
§9 表）——介于其间的请求得 `failed`。

**信息边界**：scales 公开（KL.bin）而权重隐藏；scales 由权重拟合而来 ⇒ 它们**是**权重的
函数——所以它们在"故意不隐藏"清单上，且 scale file 能关掉模型块（known-limits）。

**工具**：`weight_sums/`（独立小工具，测试会覆盖其 bin；用于审计/账目的权重和工具——
读 `weight_sums/README.md` 确认用途）；`toy/` 的 `mask_rules.py` 是掩码规则的独立 Python
复现（`quick_start_test.py` 驱动）——用第三种实现交叉检验 C++ 行为的范例。

### 作业
1. 读 `scales/README.md` 全文，画出从 GGUF 到可证明模型的全流程图。
2. 读 `scales/worst-case-bounds.md`，总结 8 个范围条件各自的"论证思路"与薄弱点。
3. （合规实验）`scales/tests/` 与 `toy/quick_start_test.py` 只用合成数据跑一遍，报告结果。
4. 思考题 200 字：为什么"权重隐藏"不与"scales 公开"矛盾？泄露 scales 泄露了权重的什么？

### 资料
`docs/model.md`、`scales/`、`toy/README.md`、`verifier/docs/parameter-file.md`。

## D5 · 测试与审计体系（0.5 课）

### 目标
会用测试套件；知道测试**不能**证明什么。

### 讲义
**套件**（`SUITE.md` + `run_suite.py`）：
```bash
D=$(mktemp -d) && ./run_suite.py cpu "$D/work"
```
- 退出码 0=通过、77=缺工具、**3=发现假接受 → 按 SECURITY.md 上报**（最高优先级事件）；
- **会覆盖 `bin/cp_verify` 与 `bin/weight_sums`** ⇒ 在仓库**副本**里跑（AGENTS 规则）；
- 套件行包括 `build.verifier`、`verifier.call_accounting.examples`、`gpu.quick_start`、
  `gpu.run_target_example` 等（SUITE.md 全表）；
- GPU 内核测试"partly, mostly at small sizes"（what-is-proved 原文）——编译器与硬件被信任，
  无独立安全审计。

**测试的边界**（`guide/known-limits.md` "How far the tests go"）：每行测试都只在特定设置/
尺寸/次数上跑过；`docs/limits.md` "What was never tried" 列出未试清单；"the reviews are not
independent"——审查链不独立。**测试通过 ≠ 定理成立**，这正是本仓库反复强调的分层。

## D6 · 服务化与运维义务（0.5 课）

### 目标
理解从"证明系统"到"生产服务"之间剩下的全部工程与制度义务。

### 讲义
**组件**：`integrations/vllm/`（vLLM 前端 + 整数模型 Python 实现）、`integrations/check_proof.py`
（客户端验证封装）、`driver/measure_rate.py` + `driver/spool.py`（速率测量与请求池）。

**铁律**：批内任何响应离开提供商之前，前端必须对其证明跑过 `cp_verify` 且全部接受
（协议 §6.3 "The check before anything leaves"；例外窄且对客户端不可用，见
integrations/LIMITS.md）。拒绝/无裁决 ⇒ 该批全部扣下 + 停机排查。

**运营商义务**（docs/operators-duties.md + limits.md "What a provider must do"）：`isk` 永秘、
永不复制/恢复（镜像重启=随机源重复=灾难，C5）；任何响应未经验证不放行；计数器不可
重置；批重叠默认开（上一批未放行时下一批已在证明——停机可能扣住更早的批）；自检失败
立即停服。

**真模型全流程**：`examples/maverick/run.sh`（README）——下载公开 4-bit 转换（232GB）、
校准、承诺、服务、验证，五个期望值逐一比对（what-is-proved 记录：曾在发布程序上全流程
跑通一次，cp_verify 以 YES 收尾）。学习阶段只读不跑（需要 H100/330GB RAM）。
