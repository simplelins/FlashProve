## 3. 八个核心对象：论文定义 → 白话

### 3.1 随机预言机与查询数 q（§2.1, Def 2.1）
论文把哈希函数理想化为"每个输入独立均匀随机输出 256 位"的函数 H。任何算法（包括作弊者）
被建模为一棵**查询树**：每个内节点问一次 H，叶是输出。**q = 树上任一路径最多的查询数**。
作弊者每改一次消息 = 多一次查询。这就是主定理误差里"每查询 2^-124"的语义：作弊预算 q
越大越容易作弊，误差线性涨。

### 3.2 掩码编码与承诺表（§4.2, Def 4.1/4.2）——权重隐藏的代数核心
**白话**：把所有权重写成 base-256 带符号数字（Emb 每项 4 个数字、其余每项 2 个；数字 ∈
[−2^7,2^7)，两数字合成 b0+2^8·b1 ∈ [−2^12,2^12)），按公开规则摆进一个 **d=3,076,096 行 ×
2^18 列的数字矩阵 A**（约 8×10^11 格 ≈ 400.7B×2 个数字 ✓）。矩阵每一**列块**成表的行：
表的 2^v=2048 行，每行消息 f_r 长 ℓ=402,653,184（含 3 个 OOD pad 元素）。
**掩码编码**（Def 4.2，逐项读）：
```
Enc(f; τ) 在点 φ 处的值 = Σ_{j<t} τ_j·φ_j + Σ_{j<ℓ} f_j·φ_{t+j}
```
即：把"消息 f（ℓ 项）+ 随机系数 τ（t 项）"看成同一个 deg<(ℓ+t) 多项式的系数，在 |D|=2^32
个点上求值。**任何 t 列与权重独立**（Theorem 6.3），t+1 列开始泄露（Prop 6.5：A=0 与
A'[0][0]=1 在 t+1 列 + OOD 答案下分布可区分）。**t=44,040,191 就是开列预算**。
Table 2 关键数：码率 ρ=(ℓ+t)/|D|=0.1041；接近参数 δ=0.664（论文取"严格低于 Johnson
半径"：Johnson = 1−√ρ = 0.677 > 0.664 ✓，可自己验算）；解码半径 e=2,852,142,980 列。
**为何 δ 大反而省**："A word at relative distance δ passes ν sampled positions with probability
(1−δ)^ν, hence a larger δ requires fewer opened columns"（§4.3）——允许的偏离越大，抽查的
列越少，证明越短，预算内能跑的证明越多。

### 3.3 OOD 采样与解码器（Def 4.3/4.5）——"钉死唯一消息"
δ=0.664 超过唯一解码半径（(1−ρ)/2≈0.448），所以一个词附近可能有**多个**码字（list）。
解法：每个表在**建表时**发布一组"掩码的行求和"（OOD answers）：
```
a_{r,i} = Σ_j eq(z_i, j)·f_r[j] + β_i·pad_{r,i}
```
其中 (z_i, β_i) 是种子（**从表根派生**：Seed(rt)，两次 H 查询），pad 是行尾随机元素。
解码器 Dec（Def 4.5）三步：①若两个**不同消息**的候选码字给出相同 OOD 答案（collision）
→ ⊥；②否则取"给出这些答案的最近码字"；③从其 mod p 余数读出数字矩阵 A，检查在范围内。
白话：附近可能有多个候选，但它们要在随机点上给出**同一个**值——不同消息的多项式在
随机点撞值的概率 ~deg/|E|，极小 ⇒ 答案唯一确定了消息。
**安全顺序规则**（foldeq.h L228-230 同款）："The answers must come before every gamma: a
prover that knows gamma first fits them to any close table."

### 3.4 三个 IOP 与它们的"语言"（Construction 4.13 的表，务必抄进笔记）

| IOP | 实例 | oracle 串 | 语言 L（作弊者必须让验证者相信的话） |
|---|---|---|---|
| IOP^key | σ₀（anchor 的 OOD 样本） | T*₀ | "T*₀ 有碰撞 **或** Dec≠⊥"（注：语言是说"坏情况发生"——RBR soundness 的状态函数把"接受且语言为假"记为坏事件） |
| IOP^link | (σ₀, σ_j) | T*₀, T*_j | Def 4.6 的三臂析取：Dec(T*₀)=⊥ 或 Coll(T*_j) 或 Dec(T*_j)=Dec(T*₀) |
| IOP^req | (ξ, σ_j) | T*_j | "Dec=⊥ 或 (Dec(T*_j), ξ) ∈ Req_Z" |

**白话**：key 证明"第一张表是个合格的码字表（能解码出范围内的矩阵）"；link 证明"副本表
解码到同一个矩阵"；req 证明"（这个矩阵，这个请求）满足请求关系 Req_Z"。
**Req_Z**（Def 4.8/4.9）：模型按 **G=25 个 segment** 切分，每段有 cells（中间值矩阵）、
identities（方程）、lookups（查表键）。(A,ξ)∈Req_Z ⟺ 存在 |值|<2^18 的 cells 使所有方程
mod p 成立、所有查表键在表内。**Lemma 4.9 [machine-checked]** 把它翻译成人话：⟺ ①模型
在窗口上有定义；②被检 token 的 logit gap 满足策略两个界；③若窗口满，y⁺ 是 greedy。

### 3.5 论证 Π_Z 与提取器（Construction 4.15）
验证器九步：①范围测试（配置合法）②拆包证明 ③公开读数 ④build(x,y,fill) 合法 ⑤
**H(code(k,dg_Z)) = c**（承诺 ID 就是这样验的！）⑥三个文件非空 ⑦OOD 种子 = Seed(root)
⑧依次跑三个编译验证器 ⑨副本编号核对。**提取器 Ext_Z**（不查询、直接函数）：从作弊者的
查询轨迹里找"答案=c 且查询=code(k,dg)"的首条 → 把轨迹翻译成 Merkle 查询 → 重建 T*₀ →
返回 wt(Dec(T*₀,σ₀))。
**关键认知**（Remark 4.16）：在 Lean 项里 Π_Z 的 committer/prover 是**常函数**（发固定消息）
——所以 soundness 定理只关于验证器+提取器；completeness/ZK 才需要诚实的 Lean prover。

### 3.6 主定理 Theorem 5.1（§5.1）
```
ε(q) = 16T/2^128 + (T+2)²/2^256,   T = q + 1 + 2^23
```
- **T 的构成**：q（作弊者查询上界）+ 1（验证器第 2 步的一次查询）+ 2^23（验证器其余步骤
  的查询配额，§5.6）。
- **为何 ≈ q/2^124 + 2^-101**：16T/2^128 = T/2^124 ≈ (q+2^23)/2^124 = q/2^124 + 2^23/2^124 =
  q/2^124 + 2^-101；第二项 (T+2)²/2^256 在 q≪2^116 时 ≤2^-101 量级。**124 bits/查询**，
  下限 ≈2^-101。
- **证明四步**（§5.6，每个作弊只有这四种死法）：①编译引理——事件 Bad（新答案重复轨迹
  值 / IOP 状态 0→1 / OOD 种子有碰撞）的概率 ≤ Q·ε_rd + 2(Q+1)²/2^256，Q=5T；Bad 之外，
  接受 ⇒ 三张表解码成功且 (A,ξ)∈Req_Z；②轮误差 ≤ ε_rd=2^-128（Prop 5.14，PoW 计入；
  无 PoW 则 2^-96..2^-110；整个未编译运行 67,391·2^-96 < 2^-79）；③Req_Z ⇒ 策略满足
  （Lemma 4.9/A.33）；④误差求和给出因子 16（"not tight"）。
- **Corollary 5.10**：N 个证明同时提交 ⇒ N·ε(q)。

### 3.7 承诺三定理（§5.5）——"提取出的就是你放进去的"
Def 5.16 显式承诺者（用 coin map Γ 从 seed 派生全部随机性；**2^35+2 次 H 查询**）：
- **Thm 5.17**：correctness of extraction 误差 **β(2^35+2) ≈ 2^-89**；extractability β；no-two-
  openings 2β。其中 β(q)=16(q+2^23)/2^128 + (q+2^48+2^23+2)²/2^256。
- **Prop 5.18**（更紧）：γ(q)=3(q+2^49+4)²/2^256，γ(2^35+2) ≈ **2^-156**。
- **Thm 5.19**：在**承诺的权重本身**下，被接受的输出满足策略的概率误差 ε_com ≈ **2^-88 +
  q_P/2^124**。
- **范围**（Remark 5.21）：只对"显式承诺者"（模拟 cp_commit 的一部分）+"值级比对"过发布
  程序†；Chk(Z)=1 只在 Z0 与只改策略的配置上机器检查过；显式承诺者没有诚实 prover——
  "no proof is shown to be accepted under its commitment"。

### 3.8 零知识：三层结果（§6）
- **Thm 6.3（表实验，编译前）**：开列预算内，"OOD 答案 + 任意抽的列"的分布与权重**完全
  独立**（A 与 A' 同分布）。但**不是** index privacy——不覆盖 prover 从权重算出的消息；
  且released 程序的两个现实条件**不被覆盖**：PRF 派生随机性（Remark 6.4）、种子从根哈希
  派生。
- **Prop 6.5**：预算是紧的——t+1 列即可区分。
- **Thm 6.6 + Cor 6.7（编译后，whole-key 论证）**：index privacy 归结为每 prover 5 条件；
  常量消息 prover + 新鲜均匀随机 + PoW 搜索上限 2^40 + 盐 320 位下：K=N=1 时误差
  **ζmax ≤ 2^-135**；K=710,324、N=688,127 时 **< 2^-97**。**四个不覆盖**：20 条件中 5 条
  是"从 Lean 证明的调用里读出来的"、非常量消息的 prover 输出、承诺是整个 key 而非 256 位
  ID（"No statement transfers either result to Π_Z"）、单请求非批。
- **每请求 1 bit**（§6.5/Limitation 8.3）：served/refused 依赖权重；多请求可推断模型输出；
  无定理界累积泄漏。§6.5 还有 completeness（served 请求上拒绝概率 ≤2^-40）——细节配合
  `lean/THEOREM.md` 读。

## 8. 论文里最容易被误读的六句话（防呆清单）

1. "soundness of the Lean verifier" ≠ "soundness of the system"（8.1）；
2. "ZK" 是 index privacy 的近似词，且只对 Lean provers + 单请求 + 整 key（8.3、Remark 6.8）；
3. "clipped gap 下被接受"几乎可以是任何输出（8.8 + Prop 3.9）；
4. "688,127" 是程序计数器的批上限，**不是** Lean ZK 结果的计数口径（8.4 末段明说两者
   "counts another thing"）；
5. "16.15B used per token"（Table 8）是论文口径；model.md 推导 17.2B 是全额口径——差在
   Emb/Wh 计法，引用时注明；
6. §1.3 的署名事实：论文与程序几乎全部由 AI 在人类指导下写成，"no person has checked"
   其报告的测试/计算/阅读/审查——这句话本身就是论文诚实性的一部分。
