## A1 · 有限域：Goldilocks 与它的扩域（1 课）

### 目标
掌握 F_p 与扩域构造；理解本系统选 p=2^64−2^32+1 和三次扩域的原因。

### 讲义
**域**：F_p = {0,1,…,p−1}，加乘模 p。p 素数 ⇒ 非零元都可逆。所有协议数值都在这个域上；
"减法"是把模 p 的同余方程当整数方程读的前提（所以有范围检查，见 B5/C3）。

**Goldilocks 域**：p = 2^64 − 2^32 + 1（61 bit，"2^64 级别"）。两条恒等式让 64 位机器乘法
便宜：
- 2^64 ≡ 2^32 − 1 (mod p)。把乘积 a·b 写成 (a_hi·2^64 + a_lo)·… 后，高 64 位 ×(2^32−1) 即可
  折回；
- 2^96 ≡ −1 (mod p)（因为 2^96 = 2^64·2^32 ≡ (2^32−1)·2^32 = 2^64−2^32 = p−1）。
这两条你可以自己用 Python 验证（作业 1）。

**扩域**：挑战不从 F_p 抽，而从 **E = F[X]/(X³ − c)** 抽（默认 c=2；blocks 规则 2：
`-DBLK_FIELD=2`，Goldilocks、X³−2、plain Reed-Solomon——它是唯一被编译进程序的域）。
|E| = p³ ≈ 2^192。为什么需要扩域：每轮 soundness 误差 ~ (Σ deg)/|域|，2^64 < 2^128 目标，
不够；p³ > 2^192，单轮误差轻松 < 2^-128。协议 §5 开头一句"Random challenges come from a
larger field built on it"说的就是它。

**规范表示**：域元素必须以规范形式编码（< p）。验证器拒绝非规范元素——这就是十组检查里
"no byte is left over / field elements below the prime"（R0.1, R1.3），防止一个文件有两种读法
（例如把 ≥p 的字节序列解释成两个不同元素）。

### 在 FlashProve 中的位置
- `blocks/field/`：F 与 E 的实现、"canonical parsing, one attempt at a draw"、等值向量、小多项式。
- blocks 规则 2：任何地方不得硬编码元素宽度，宽度只由 `field/`、`hash/` 决定——这是防
  "改一个常量悄悄削弱域"的工程手段。

### 作业
1. Python 验证两条恒等式：`p=2**64-2**32+1; assert (1<<64)%p == (1<<32)-1`；再验 2^96 ≡ −1。
2. 实现_mul_mod_：输入两个 64-bit 数，输出 a·b mod p（可用 Python 大整数对拍）。
3. 实现 E 的加法与乘法：元素 = (e0,e1,e2) ∈ F³，乘法按 (X³=c) 归约。验证 c = 2 在 E 中无
   立方根（即 X³−2 不可约——用穷举 F_p 检查 X³=2 无解）。
4. 读 `blocks/field/` 目录清单，找到规范解析（canonical parsing）的代码位置。

### 自测与答案要点
- **为什么挑战要用扩域？** 每轮误差界里分母是挑战域大小；F_p 只有 ~2^64，扩域 p³ 提供
  >192 bit 的分母。
- **为什么拒绝非规范编码？** 防止同一文件有两种合法读法（歧义 = 可拼接 = 可作弊）。
- **X³−c 取 c=2 有什么好处？** 2 在 F_p 中无立方根 ⇒ X³−2 不可约 ⇒ 扩域确实是域。作业 3
  穷举即可验证（2^((p−1)/3) ≠ 1 类判据的暴力版）。

### 资料
协议 §5 引言；`blocks/README.md` 规则 1–2；任何一本抽象代数讲义的有限域章节（够用即可）。

## A2 · 多项式与 multilinear（1 课）

### 目标
掌握两种多项式表示（系数 / 求值表）与 multilinear 扩展；吃透 **fold** 运算——它是后续
sumcheck、承诺折叠、code switching、共享链共同的原语。

### 讲义
**单变量多项式**：deg < k 的多项式由 k 个系数唯一决定；也可以由它在 k 个不同点的取值唯一
决定（Lagrange 插值）。RS 码（A3）就是"取更多点的值"。

**multilinear 多项式 (MLP)**：m 个变量、每个变量次数 ≤1。标准表示是 2^m 个数的表
t[b]（b ∈ {0,1}^m）。其扩展：
```
M(x) = Σ_{b∈{0,1}^m} t[b] · Π_i eq(x_i, b_i),   eq(x,b) = x·b + (1−x)(1−b)
```
模型计算中的任何"中间值表"（trace）都可以看作 MLP：sumcheck 只需要 MLP 形态就能跑。

**索引约定**（blocks 规则 3，代码里到处是它，必须内化）：
- 索引 bit 0 = 最低位 = **第一个变量**；
- 2^k 行 × 长 l 的表 = 向量，元素 (行 b, 位置 c) 存放在 b + 2^k·c —— 行变量在前；
- **fold at g**：把第 2b、2b+1 行合成一行：(1−g)·row_{2b} + g·row_{2b+1}。
  对折叠后的表再取 MLE，等于原 MLE 在 x_1 = g 处的部分求值（作业 2 让你亲手验证）。

**为什么 fold 是核心**：sumcheck 每轮用挑战 r_i 把变量 i "折掉"；承诺折叠（把多个承诺的行
随机线性组合成一个）降低验证者要检查的对象数；code switching（B4）把"长码上的多行"折成
"短码上的少行"；共享链（C3）用块因子折叠权重表。同一个代数动作，出现在四个地方。

### 在 FlashProve 中的位置
- `blocks/iop/tensor.h`：结构化系数向量；`blocks/iop/relation.h`：oracle 消息/组/带公开目标的行/掩码。
- 证明器里的 trace = 每段的中间值表（整数模型的中间值写成域元素）。
- `verifier/src/vf_sumcheck_*.h`、`vf_layers_*.inc`：验证端对折叠/求值的重算。

### 作业
1. 实现 `eq(x, b)` 与 MLE 求值：m=3 的随机表 t，随机 x∈F³，验证 M(x) = Σ t[b]·Π eq(x_i,b_i)。
2. 实现 fold：对 t 沿变量 1 以随机 g 折叠得 t'（2^(m−1) 行），验证 M'(x₂..x_m) = M(g, x₂..x_m)。
3. 读 `blocks/README.md` 规则 3 原文，解释"row variables first"为什么影响 b + 2^k·c 这个公式。

### 自测与答案要点
- **MLP 为什么对 sumcheck 友好？** 每轮单变量次数 =1，验证者对单轮消息的检查只需 2 个点
  的值；误差界 m/|E| 线性于变量数。
- **fold 后表的行数、语义？** 行数减半；每行是原表在 x_1=g 处沿 c 方向的部分求值。

## A3 · Reed–Solomon 码与权重隐藏（1 课）

### 目标
掌握 RS 编码、距离、list decoding/Johnson 半径；**理解"任意 t 个编码值看起来均匀随机"——
这是整套权重隐藏的代数基石。**

### 讲义
**RS 码**：在 F_p 上取长度 n 的求值域，消息（deg<k 多项式的系数）编码为它在 n 个点的取值。
最小距离 d = n−k+1（Singleton 界，RS 是最优的）。两个不同消息的编码在 ≥ d 个位置不同。
- 唯一解码半径：(d−1)/2——这个球内只有一个码字；
- **list decoding / Johnson 半径**：允许的"接近"距离大于唯一解码半径时，球内可能有**多个**
  码字。相对半径 1−√ρ（ρ = k/n 为码率）。FlashProve 的 proximity test 正是工作在 Johnson
  半径（协议 §5.5 明说 "The tests allow distances up to the Johnson radius, at which several
  codewords can be close"）——多个候选码字的存在是 OOD 采样（B6）的动机。

**隐藏性质（ Shamir 型论证）**：把行向量写成"消息 + t 个随机元素"定义一个多项式 f，
编码 = f 在 n 个点的值。**任取 ≤ t 个编码值，其分布均匀随机，与消息无关**——因为那 t 个
随机系数在这些点上的取值矩阵是 Vandermonde 的子矩阵，可逆 ⇒ 取值是随机系数的双射。
这就是协议 §5.1 的"any t values of an encoded row look random, whatever the weights are"。
**t 叫 query bound**（≈ 随机元素个数）：打开的列数 ≤ t 之前，观察者什么都学不到。

**权重表的构造**（协议 §6.1 步骤 1）：
1. 所有权重写成小的带符号 base-256 **数字位**，排成权重矩阵 M（M[i,j] = 位置 (i,j) 的数字位）；
2. 把 j 轴切成**块**：权重表的**一行** = 固定 i、块内所有 j 的数字位（"表的行不是 M 的行"！）；
3. 每行加随机元素 → RS 编码 → 行拼接成表；**列** = 所有行在同一位置的值；对列建 Merkle 树。
"row ≠ M 的 row"是新手第一陷阱：折叠/开列都以"表的行=块"为单位（C3 共享链的块因子）。

**磨损**：每批证明要打开一些列 ⇒ 消耗随机性预算。程序先写磁盘计数器再开列（协议 §6.3
步骤 2），保证计数严格先于打开。默认设置下一个 leaf table 至多服务 688,127 批（程序自己的
记账，不是安全级别）。

### 在 FlashProve 中的位置
- `blocks/code/`："a code = (length, message length, length of the random tail)"——注意消息长度
  和随机尾巴长度是分开记录的，t ≈ 尾巴长度。
- `docs/protocol.md` §5.1、§6.1、§6.3；`docs/limits.md` "Weight hiding" 节。

### 作业
1. 实现 toy RS：p 小素数、n=16、k=5（含 2 个随机尾巴）。验证任意两条消息编码距离 ≥ 12。
2. 隐藏实验：固定消息、随机尾巴重采样 1000 次，取前 t=2 个编码位置的值做直方图/卡方，
   验证均匀；t=3 时（>尾巴数）验证开始泄偏。
3. 读 `blocks/code/`：找到 (length, message length, tail) 三元组的定义与编码函数。
4. 解释：为什么"先写计数器再开列"用磁盘而不是内存？（提示：崩溃后重启不能"忘账"。）

### 自测与答案要点
- **隐藏与 ZK 的关系？** 这里是信息论式的随机性隐藏（编码性质），是整个系统 ZK 论证的
  一半；另一半是掩码/盐（A4、C5）。
- **为什么工作在 Johnson 半径而不是唯一解码半径？** 更大的允许距离 ⇒ 更短的证明（更少的
  采样点），代价是要 OOD 采样钉死消息。工程换安全预算。
- **权重表的一行是什么？** 某个 i 下、j 块内所有数字位 + 随机元素，经 RS 编码。

库把所需的编码理论在库内自证（阶段 E 详述这个重要差别）。

## A4 · 哈希承诺、Merkle 树与 Fiat–Shamir（1 课）

### 目标
掌握 Merkle 承诺 + 盐、Fiat–Shamir hash chain、proof of work 的角色；理解"public inputs 必须先
于挑战被绑定"这条铁律。

### 讲义
**Merkle 承诺**：对 n 个列各算叶哈希，两两向上得根。承诺 = 根；打开 = 叶 + 路径。
验证者重算根。抗碰撞哈希 ⇒ 承诺后改不了叶。**盐（salt）**：每叶带随机盐才哈希
（blocks/tree："one kind of leaf (a column and its salt)"）。没有盐，攻击者可离线暴力猜未打开
列的内容并对照根验证（R7.3 明说 salt 就是防这个的）。

**Fiat–Shamir hash chain**（协议 §5.6）：证明是文件，没有交互方发挑战 ⇒ 证明者维护一个
"运行中的哈希"：每个挑战 = H(链当前值 ∥ 证明者最新消息)。要点：
- **链的输入** = 参数摘要 + 32 随机字节 + 陈述内容（哪个权重表、哪个请求……）；
- **label**：每条链带协议编号标签进哈希——不同文件里的同种链不可互换；
- **round** = 证明者一条消息 + 紧随的挑战；链尾的摘要叫 **seal**，后续链把前链的 seal 吸进
  自己的输入（防"拼接两次运行的片段"——验证端十组检查之一）；
- **proof of work**：默认设置要求在"采样位置"的轮次前做哈希搜索（R5.5）。它提高的是
  grinding 的每次重试成本；注意 terms.md 的精确措辞：它计入 target，但**不会降低**假陈述
  在一次挑战下存活的概率。

**grinding 与安全界的关系**：作弊者每改一条消息 = 一次哈希查询。总伪造概率随哈希查询数 q
线性增长——这就是 Lean 定理里 "q/2^124 + 2^-101" 中 q 的来源（阶段 E）。

**public inputs 先绑定**（blocks 规则 10，经典 FS 陷阱）：任何不进链输入的公开量，证明者都
可以在看到挑战之后挑。所以 blocks/ 用 `Binder` 把参数和陈述写进第一条查询，返回的
`Public<T>` **没有 getter**——只有这条链的 channel 能读它，想绕过类型系统作弊得刻意写。

**两类哈希**：BLAKE2b（Merkle/FS/承诺 ID）+ 一个基于 BLAKE2b 压缩函数的**第二个固定哈希**
（把九个摘要喂进证明陈述；在已发表的 BLAKE2b 分析范围之外——known-limits 点名这一条）。

**私有随机性**：程序用 ChaCha20 从秘密 seed + 系统新鲜字节派生随机数（`blocks/coins/`）。
所以程序的隐藏是**计算性**的，且 limits.md 指出派生方式按字面读不完全满足技术报告的打印
条件（阶段 E 审计清单条目）。

### 在 FlashProve 中的位置
- `blocks/hash/`：BLAKE2b 按规格实现（leaf/vertex/轮次/参数摘要四类调用）；
- `blocks/chain/chain.h`：带 PoW 的链；`chain/public.h`：Binder/Public；`chain/rounds.h`：类型化轮次；
- `blocks/tree/`：完美二叉树、列+盐叶、批量开列。

### 作业
1. 实现 toy Merkle（8 叶，含盐）：开 3 叶验证通过；改 1 个未开叶的盐值验证根变化。
2. 无盐攻击实验：树叶子承诺"8 个数中的一个"，攻击者枚举 0..255 能否暴力猜出未开叶？
   加盐后为什么失败？（用 toy 代码跑出来。）
3. FS 转录实现：把 A 阶段留的 sumcheck 骨架接到链上（挑战取 H(transcript) mod p）。
